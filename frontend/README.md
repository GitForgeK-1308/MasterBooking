# MasterBooking Frontend

React + Vite фронтенд для API проекта MasterBooking.

## Запуск

Backend должен быть доступен по адресу `http://localhost:8000`.

```bash
cp .env.example .env
npm install
npm run dev
```

Frontend откроется на `http://localhost:5173`.

## Возможности

- регистрация, вход и восстановление пароля;
- профиль пользователя и загрузка аватара;
- каталог услуг, категории, поиск, цены и география;
- страница услуги, фотографии, отзывы и свободные слоты;
- создание и отмена записи, отзыв после завершённой записи;
- подтверждённый переход клиента в роль мастера через создание профиля;
- кабинет мастера: записи, услуги, фотографии, расписание, отзывы и профиль;
- структурированная админ-панель с отдельными подразделами «Каталог» и «Локации»;
- подразделы администратора: категории, теги, города и районы;
- создание и редактирование справочников;
- включение/скрытие категорий и тегов.

## Администратор

Роль администратора назначается на backend, например при локальном запуске:

```bash
cd backend
uv run python make_admin.py admin@mail.ru
```

После этого выйдите из аккаунта во frontend и войдите снова.

## API URL

`.env`:

```env
VITE_API_URL=http://localhost:8000
```

## Примечание про аватар

Текущий `GET /users/me` backend не возвращает `avatar_url`. Поэтому frontend использует `avatar_url`, полученный из `POST /users/me/avatar`, и сохраняет его локально для конкретного пользователя. Если позже добавить `avatar_url` в `UserResponse`, frontend уже умеет предпочитать значение, пришедшее с сервера.

### Иерархия категорий

Категории отображаются каскадом. Корневая категория (например, «Стрижка») выбирается первой, после чего интерфейс предлагает её дочерние категории («Мужская», «Женская» и т. п.). На главной странице показываются только корневые категории. В каталоге выбор родительской категории фильтрует также услуги из её дочерних категорий.

## Последние улучшения интерфейса

- каскад категорий переработан в вертикальные шаги, чтобы он аккуратно помещался в фильтрах;
- карточки услуг показывают полный адрес и рейтинг мастера;
- при создании услуги можно сразу выбрать основную фотографию;
- в кабинете мастера доступна полноценная фотогалерея услуги: массовая загрузка, выбор основной фотографии и удаление;
- в отзывах мастера название услуги отображается отдельно и заметно.

## Аватары и фотогалерея

- При создании услуги можно выбрать отдельную основную фотографию и сразу несколько дополнительных фотографий галереи. Основная отправляется на backend первой, поэтому существующая логика `is_primary` делает её основной автоматически.
- И клиент, и мастер могут загружать/менять аватар через `/users/me/avatar`.
- Кнопка удаления аватара использует `DELETE /users/me/avatar`. Для неё нужен небольшой backend-патч, приложенный отдельно к обновлению фронтенда.

## Мастер как клиент

- Мастер может открывать каталог и записываться к другим мастерам через тот же сценарий бронирования, что и обычный клиент.
- В мастерской добавлен отдельный раздел «Мои записи» для личных визитов мастера; «Записи клиентов» остаются отдельным рабочим разделом.
- После успешной записи мастер автоматически попадает в «Мои записи».
- Собственные услуги помечаются в каталоге бейджем «Ваша услуга».
- На странице собственной услуги вместо формы бронирования показывается понятное сообщение и кнопки управления услугой / поиска другого мастера.
- Фронтенд рассчитан на backend-проверку, которая разрешает CLIENT и MASTER создавать бронирования, но запрещает мастеру бронировать собственную услугу.

Примечание: создание отзывов для мастера пока не показывается в разделе личных записей, потому что текущий backend endpoint отзывов всё ещё использует зависимость `get_current_client`. Это можно расширить следующим backend-шагом на ту же `get_current_customer`.


## Состояние отзывов в бронированиях

Frontend ожидает поле `has_review: boolean` в `BookingResponse`. Для завершённой записи кнопка «Оставить отзыв» показывается только при `has_review === false`. После успешной отправки состояние обновляется сразу локально, а после перезагрузки берётся заново из backend через `/users/me/bookings`.
